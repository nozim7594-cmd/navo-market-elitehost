# Navo Market

Telegram Mini App на узбекском. Свой интерфейс: тёмный индиго, янтарные акценты, каталог, фильтры, избранное, кошелёк, аренда и админка.

## Что готово

- Node.js 22.13+, SQLite, TON SDK для подписи транзакций.
- Проверка Telegram initData по HMAC, проверка срока сессии, серверная проверка администратора.
- Реальные активы добавляются через админку. Пока каталог пустой, показываются явно помеченные образцы, их нельзя арендовать.
- Баланс в TON, хранится целым числом в миллионных долях TON.
- Stars: пользователь вручную вводит сумму; сервер создаёт настоящий XTR invoice. Баланс пополняется только после successful_payment из защищённого webhook Telegram. Повторная доставка события не зачисляет деньги снова.
- Крипто: пользователь переводит TON на настроенный адрес и указывает сумму и hash. Администратор самостоятельно проверяет сеть, адрес назначения, сумму и факт окончательного зачисления перед подтверждением. Введённая пользователем сумма сама по себе не подтверждает перевод. USDT и другие сети пока не поддерживаются.
- Аренда: атомарное списание баланса, запрет двойного бронирования. Администратор передаёт актив вручную и нажимает «Berildi»; только тогда начинается срок аренды. Отмена ожидающей выдачи возвращает деньги ровно один раз.
- Список аренды и платежей доступен только владельцу. Админка — только Telegram ID из ADMIN_IDS.

## Запуск

```bash
cp .env.example .env
# Заполните .env локально, не отправляйте токен в переписку.
npm ci
npm test
npm start
```

Node.js 22.13+. Откройте http://localhost:3000 для просмотра. Без Telegram можно только просматривать. Для платежей нужен HTTPS и настоящий Telegram Mini App.

Переменные .env:

| Имя | Назначение |
| --- | --- |
| BOT_TOKEN | Токен своего бота из @BotFather |
| BOT_USERNAME | Username своего бота |
| ADMIN_IDS | Числовые Telegram ID администраторов, через запятую |
| PUBLIC_URL | HTTPS-адрес сервера Mini App |
| CRYPTO_WALLET | Адрес получения TON в сети TON mainnet |
| STARS_PER_TON | Курс: сколько Stars зачисляются как 1 TON внутреннего баланса |
| TELEGRAM_WEBHOOK_SECRET | Случайная строка из A-Z, a-z, 0-9, _ и -, 32+ символа |
| DB_PATH | Путь к SQLite, по умолчанию ./navo.sqlite |

Сгенерировать секрет: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.

После настройки HTTPS и PUBLIC_URL:

```bash
node --env-file=.env scripts/configure-bot.mjs
```

Скрипт устанавливает webhook и кнопку меню Bozor у вашего бота. `/start` отдаёт кнопку запуска приложения. В @BotFather задайте домен/настройки Mini App при необходимости. Запустите приложение из бота под ADMIN_IDS: в меню появится «Boshqaruv». Добавьте ваши настоящие активы. Сторонние активы с сайта-образца сюда не импортируются.

## Продакшен

```bash
docker compose up -d --build
```

Настройте HTTPS reverse proxy на 127.0.0.1:3000. Пример Caddy:

```caddy
market.example.uz {
    reverse_proxy 127.0.0.1:3000
}
```

Замените домен своим. SQLite сохраняется в Docker volume navo-data. Делайте резервные копии с помощью SQLite backup API или после остановки сервиса; не копируйте только основной файл при активном WAL. Используйте один экземпляр сервера, чтобы транзакции и SQLite оставались согласованными.

Опубликованный в Sites вариант — просмотр интерфейса. Sites в этом проекте обслуживает статические файлы; Node.js/SQLite сервер нужно развернуть отдельно. Этот адрес не является рабочим платёжным backend и не должен использоваться как PUBLIC_URL бота. По умолчанию Sites доступен только владельцу. Для клиентов используйте свой HTTPS-домен с сервером из этого репозитория.

## Границы реализации

Бот, токен, ID администратора, кошелёк и домен пока не предоставлены. Реальные платежи и запуск через бота не настроены и не проверены. Автоматической передачи/возврата NFT, номеров и username нет: выдача и возврат выполняются владельцем вручную. По окончании срока актив переходит в очередь возврата и остаётся заблокированным для новых аренд, пока администратор не вернёт его в своё владение и не подтвердит возврат в админке. Для автоматической выдачи нужна отдельная интеграция с системой хранения активов.

Витрина использует локальные WebP-изображения моделей Telegram Gifts из публичной коллекции https://github.com/sendboc/Gifts-Assets. Модели в примерах не являются предложением аренды конкретных серийных NFT. Курсы вводит владелец. Stars не считаются оплатой до подтверждённого webhook. Крипто автоматически в блокчейне не проверяется. Отдельные возвраты Stars, споры и вывод средств не реализованы; внутренний баланс предназначен для оплаты аренды.

## Проверка

`npm test`: подлинность Telegram, срок сессии, запрет чужого доступа, однократное зачисление, изоляция пользователей, атомарная аренда, повторная бронь, возврат и Stars webhook. Внешние Telegram-вызовы в тестах заменены имитацией. Браузерная проверка ограничена недоступностью облачного браузера в текущем окружении.


## Подарки MarketApp

Сервер с MARKETAPP_API_TOKEN читает каталог GET /v1/rent/gifts/ постранично по курсору: до 100 страниц по 100 записей, если поставщик не отдаёт меньше. Кэш каталога — 30 секунд. В заголовке Authorization передаётся только токен.

Цена в карточке включает наценку MARKETAPP_MARKUP_PERCENT (10% по умолчанию). Перед оплатой сервер получает свежий каталог и транзакцию /v1/rent/{address}/pay/. Итог — большая из стоимости срока и суммы сообщений с заданным резервом сети, плюс наценка, с округлением вверх до миллионной TON. Пользователь отдельно подтверждает итог. Резерв MARKETAPP_NETWORK_RESERVE_NANO указывается в нанотонах (1 TON = 1 000 000 000). Владелец устанавливает его с учётом сети и экономики приёма платежей.

Для выдачи настройте отдельный операционный TON-кошелёк V4R2 на mainnet, на котором создан токен MarketApp, и поддерживайте его баланс. MARKETAPP_WALLET_ADDRESS и MARKETAPP_WALLET_MNEMONIC задаются в секретах сервера. TONCENTER_API_KEY опционален. Перед первой продажей проверьте соответствие адреса и токена и сделайте согласованную тестовую аренду. Биржевой депозитный адрес и пользовательский кошелёк клиента для подписи не подходят.

Сервер резервирует баланс, подписывает одобренную транзакцию и опрашивает /v1/rent/my-rented/. После подтверждения вызывает /v1/rent/{address}/tonconnect/ со ссылкой клиента из Fragment. Если ссылка устарела, клиент вводит новую в «Ijaralarim». Для заказов MarketApp не нужна выдача администратором. При неопределённом результате отправки средства остаются в резерве, автоматической повторной отправки нет. Оператор сверяет запись marketapp_orders с историей кошелька перед возвратом. Запускайте один сервер с постоянной SQLite и отдельным кошельком. Исторические записи предыдущего поставщика сохраняются в SQLite, обращения к нему отключены.
