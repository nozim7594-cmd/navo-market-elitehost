# Navo Market в Telegram на EliteHost

Один процесс Node.js обслуживает страницу Mini App, Telegram webhook и аренду MarketApp. Бот открывает магазин кнопкой **Bozor**. Для PUBLIC_URL подойдёт HTTPS-субдомен EliteHost с rProxy.

На предоставленном экране Bot Lite (5 900 сум/месяц) включает webhook, ещё один порт, субдомены и резервные копии. Выберите ветку 22 и проверьте точную версию командой `node -v`: нужна 22.13.0 или новее, где встроенная SQLite доступна без экспериментального флага. Настройте один экземпляр. В архиве EliteHost исходные файлы лежат прямо в корне.

1. Загрузите архив в сервис Node.js и распакуйте **прямо в `/home/container`**: `server.mjs`, `package.json` и каталог `public` должны лежать рядом. Не оставляйте `public` только во вложенной папке `navo-market-elitehost`. Выполните `npm ci --omit=dev`. В панели «Запуск» задайте MAIN_FILE = `index.js`. Он запускает соседний `server.mjs`; путь к вложенной папке не нужен. При использовании панели с полем команды запуска задайте `npm start`.
2. Для rProxy `gift.novastax.uz` назначен порт `39292`; это значение по умолчанию в `server.mjs`, если панель не предоставляет PORT. Если создаёте `.env`, не оставляйте в нём другой PORT. Направьте rProxy с HTTPS-субдомена на этот порт. В переменных процесса задайте PUBLIC_URL как `https://<ваш-субдомен>`. DB_PATH должен указывать на файл в **постоянном записываемом каталоге**, который не заменяется при обновлении. Создайте каталог до запуска. Настройте резервные копии SQLite согласованно с WAL (подробности в README).
3. Перенесите имена переменных из .env.example в секреты панели. BOT_TOKEN и BOT_USERNAME берутся из BotFather, ADMIN_IDS — числовые ID администраторов. Сгенерируйте TELEGRAM_WEBHOOK_SECRET командой `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` в своём терминале. Для Stars укажите реальный курс; для TON — ваш адрес приёма. Не загружайте файл с рабочими секретами в репозиторий.
4. Токен MarketApp оформляется на https://marketapp.org/api-token. Для подписи используйте отдельный пополненный операционный кошелёк V4R2 (mainnet), на котором создан токен. Заполните его адрес, секрет подписи, наценку и резерв сети. Никому не отправляйте фразу кошелька или токены в переписке.
5. Запустите процесс. Проверьте адрес /healthz снаружи: ответ должен содержать `{"ok":true,"service":"navo-market"}`. После запуска выполните `npm run launch:bot` в окружении этого сервиса. Команда проверяет адрес, доступ к каталогу, настройки подписи и имя бота, затем устанавливает webhook и кнопку меню и считывает их обратно. Повтор только проверок: `npm run launch:check`.
6. Откройте бота и нажмите /start → Bozor. Проверьте каталог и права администратора. Полную выдачу с реальным списанием проверяйте с согласованной суммой. Локальные тесты имитируют сеть и платежи.

При недоступности npm в панели используйте её установщик зависимостей и запуск Node.js. Если тариф не даёт Node.js 22.13+, постоянное хранилище или внешний HTTPS-прокси, уточните подходящий тариф до оплаты.


Перед каждым AutoDeploy сделайте согласованный снимок базы командой `npm run db:backup -- /путь/вне/проекта/navo-before-update.sqlite` и скачайте его на отдельный носитель. Игнорирование .sqlite в Git предотвращает попадание балансов в репозиторий, но не гарантирует сохранность у хостера. Получите у оператора подтверждение пути для DB_PATH и правил обновления. Для восстановления остановите процесс, сохраните текущие файлы SQLite/WAL/SHM отдельно, поместите проверенную копию как DB_PATH в чистый каталог, затем запустите сервер. Не заменяйте базу работающего приложения.

После обновления из GitHub проверьте, что `/home/container/index.js` импортирует `./server.mjs`. При ошибке `Cannot find module .../navo-market-elitehost/server.mjs` обновите файлы из ветки `main`, затем запустите сервер: старый `index.js` ссылается на отсутствующую вложенную папку.

## Автоматические пополнения

Stars: задайте `BOT_TOKEN`, `PUBLIC_URL=https://gift.novastax.uz`, новый случайный `TELEGRAM_WEBHOOK_SECRET` и `STARS_MICRO_TON_PER_STAR=13000` (100 Stars = 1.3 TON внутреннего баланса). Установите webhook через `npm run launch:bot`. Кнопка оплаты создаёт счёт Telegram; зачисление происходит только по проверенному `successful_payment`, не по закрытию окна оплаты. Webhook нужно настроить до приёма платежей.

TON: заполните `CRYPTO_WALLET` публичным адресом вашего активного кошелька **mainnet**, `TONCENTER_API_KEY` ключом TON Center, затем установите `TON_AUTO_PAYMENTS=true`. Для приёма средств seed-фраза не требуется. Кошелёк для пополнений и кошелёк подписи аренды MarketApp — разные настройки. Не меняйте адрес при незавершённых платежах: старый адрес требует отдельной сверки.

Сервер проверяет TON раз в 15 секунд и ждёт не менее 60 секунд после транзакции. Проверяются получатель, точная сумма, уникальный комментарий, успешное выполнение и отсутствие bounce. Запись платежа и изменение баланса выполняются в одной транзакции SQLite. Повторная проверка не зачисляет платёж второй раз. Курс Stars фиксируется при создании счёта; TON зачисляется 1:1. Интерфейс обновляет баланс раз в 5 секунд, пока приложение открыто.

TON-счёт отображается 30 минут; корректный поздний перевод по этому же комментарию также зачисляется. Без комментария или с другой суммой автоматического зачисления нет: такие переводы требуют отдельной сверки оператором. Повторный перевод на уже оплаченный счёт также требует сверки. Не отправляйте второй раз на один счёт. При недоступности RPC сервер повторит сверку; курсор просмотра блокчейна сохранён в SQLite. Базу нужно сохранять между обновлениями.

Новые ручные заявки отключены (`CRYPTO_MANUAL_ENABLED=false`). Старые ручные заявки остаются в панели администратора. Ни администратор, ни клиент не могут вручную отметить счёт TON как оплаченный.

Каталог: задайте `MARKETAPP_API_TOKEN`; `MARKETAPP_CATALOG_PAGES=10` загружает до 1000 предложений. Ключ позволяет показывать каталог. Для автоматической оплаты заказа и выдачи дополнительно нужны `MARKETAPP_WALLET_ADDRESS`, `MARKETAPP_WALLET_MNEMONIC` и `MARKETAPP_NETWORK_RESERVE_NANO`; пока они не заданы, чтение каталога и пополнения баланса работают отдельно, а покупка аренды отключена. Доступность и цена перепроверяются при заказе.

Перед приёмом реальных денег проверьте небольшой платёж Stars и TON в вашем рабочем окружении. Автотесты используют имитацию провайдера; они не заменяют проверку webhook и блокчейна с вашими настройками. Правила Telegram для цифровых товаров требуют Stars (https://core.telegram.org/bots/payments-stars); перед включением TON в Mini App подтвердите применимость правил к вашей модели аренды NFT.

## Настройки nft_renters_bot

В `settings.mjs` сохранены публичные значения владельца: бот `nft_renters_bot`, URL `https://gift.novastax.uz`, адрес приёма TON `UQBw7FOxJuXHLZqpFZQorwsmxOTflIbZgz_UJSwUuHt2ekd4` и `STARS_MICRO_TON_PER_STAR=13000`. Это **1 Star = 0.013 TON, 100 Stars = 1.3 TON, 250 Stars = 3.25 TON**. Расчёт использует целое количество microTON и сохраняется в счёте до оплаты. Старые счета сохраняют свой исходный курс.

Публичные значения подхватываются после обновления и перезапуска. Переменные хостинга и `.env` имеют приоритет. Если раньше задан `STARS_PER_TON`, удалите его или явно добавьте `STARS_MICRO_TON_PER_STAR=13000`, чтобы применить новый курс. Не путайте это со значением `STARS_PER_TON`: последнее обозначает количество Stars за 1 TON.

Для реальных платежей по-прежнему нужны секреты `BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TONCENTER_API_KEY` и флаг `TON_AUTO_PAYMENTS=true`. Установка webhook проверяет, что токен принадлежит именно указанному боту. Адрес кошелька проверен на корректность формата mainnet; принадлежность и доступ к нему подтверждает владелец.
